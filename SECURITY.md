# Политика безопасности (Security Policy)

Спасибо, что помогаете делать проект безопаснее! 🙏

## Сообщение об уязвимостях

Если вы обнаружили уязвимость, пожалуйста, **не создавайте публичный issue**. Вместо этого свяжитесь с мейнтейнерами приватно, чтобы дать время на исправление до публичного раскрытия.

### Как сообщить

1. Напишите письмо/сообщение с описанием уязвимости.
2. Укажите:
   - компонент (backend / frontend / инфраструктура);
   - шаги воспроизведения;
   - потенциальное влияние;
   - предлагаемое исправление (если есть).
3. Мы ответим в течение 5 рабочих дней.

### Сроки

| Этап | Срок |
|---|---|
| Подтверждение получения | 48 часов |
| Первичная оценка | 5 рабочих дней |
| Исправление | зависит от критичности |
| Публичное раскрытие | после выхода патча |

## Критичные зоны внимания

### Секреты и окружение

- **Никогда не коммитьте `.env`** — используйте `.env.example` как шаблон.
- Реальные пароли задавайте через переменные окружения на сервере или GitHub Secrets.
- По умолчанию в `.env.example` стоят плейсхолдеры (`change_me`) — **обязательно меняйте их перед продакшеном**.

### Ключевые переменные (обязательно заменить в проде)

| Переменная | Риск при дефолте |
|---|---|
| `DB_PASSWORD` | Полный доступ к БД |
| `JWT_SECRET` | Подделка токенов |
| `REDIS_PASSWORD` | Доступ к кэшу/чату |
| `MINIO_PASSWORD` | Доступ к хранилищу записей |

### Известные ограничения текущей версии (MVP)

1. **RTMP-порт (1935) открыт** — любой, кто знает `stream_key`, может публиковать поток. Для продакшена закройте порт за VPN или добавьте `authInternalUsers` в MediaMTX.
2. **Чат без авторизации** — есть только rate-limit (1 сообщение / 2 сек). Для продакшена добавьте JWT-авторизацию на WebSocket.
3. **Админ-эндпоинты** (`POST /api/races`) не защищены RBAC. Требуется добавить роли.
4. **HTTPS** — в nginx настроен только HTTP; для продакшена добавьте TLS (certbot) и redirect 80 → 443.
5. **CORS** — backend разрешает `origin: '*'`; для продакшена ограничьте список доменов.

## Лучшие практики

- Регулярно обновляйте зависимости (`npm audit`, `docker scan`).
- Используйте HTTPS для всех внешних подключений.
- Храните записи VOD в отдельном защищённом бакете (MinIO).
- Настройте резервное копирование PostgreSQL.
